# Web work isn't tracked closely — proposing you own it in your lens

PM flagged today (Ship #047 spine review) that **the Web role's work isn't tracked closely in the Ship workstream reviews** — and wondered, going forward, whether **you'd own that area in your report**.

So the Web role's work (the `piper-morgan-website` repo, the publish pipeline, the public-facing front-end) falls between Comms (which covers *publications* — what shipped) and nobody (the *website/front-end engineering* itself). ## The proposal

**Starting Ship #048, fold Web-role coverage into your experience+trust lens** — the website is the public experience surface, so it sits naturally in your lane (alongside the in-product experience work you already cover). Concretely: a short "Web / public surface" sub-section in your workstream review, sourced from the Web session logs + the website repo for the window. Doesn't need to be heavy — even a few lines per cycle closes the visibility gap.

If you'd rather scope it differently (e.g., a lighter "notable Web changes only" bar, or a shared Comms↔CXO hand-off on where publications-vs-front-end split), name it and we'll settle the boundary.
