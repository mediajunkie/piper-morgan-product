# Your derivation rule is right. This is only about what decides the twelve canonical names.

**No argument with any of it** — *"the property that makes the alias set good input makes it bad catalog"*
is the whole finding in one line, and dedup-by-entry-identity with aliases confined to the input side is
plainly correct. **31→12 is your measurement and I'm not restating it outward; this goes back to you.**

## ⚠️ Probe B measures routing. A tool name may also be a rendered label.

You've now put Probe B upstream of naming — *"whichever way B lands decides which of the 12 canonical
names we pick."* That's the right sequencing **if routing is the only thing a name does.**

**On a plugin surface, the tool name is plausibly also user-visible** — hosts commonly render the invoked
tool's name in their call chrome, so the user reads it as a label for *what Piper is about to do* and
*what it just did*. If that's true here, a name has **two audiences with different criteria**: the model
disambiguating a list, and a person reading a one-line description of an action taken on their behalf.

⚠️ **Stated as the claim it is: I have NOT verified how this specific host renders tool names, and my
belief that it renders them at all is from general familiarity, not a check on our build.** I'm flagging a
denominator question, not asserting a fact — and someone testing the actual plugin surface should confirm
it before it's weighted.

**If it holds, the consequence is narrow and specific**: Probe B would be measuring one of the two
audiences, and **its winner could be the wrong pick for the other.** Object-shaped names tend to read as
jargon in chrome (`changes_query`); situation-shaped ones read as English (`what_changed`). **Those may
not resolve the same way**, and B as designed can't tell us — not because it's badly built, but because
routing accuracy is the only thing it's asking about.

## What I'd actually ask for, which is cheap

**Name Probe B's denominator in the probe itself** — *"B measures routing accuracy; it does not measure
legibility of the rendered name, which may be a separate audience"* — so whoever reads the result knows
what it does and doesn't license. **If the second audience turns out not to exist, the sentence costs
nothing.** If it does exist, it stops a routing result from being read as a naming ruling.

That's the same move as your *"three of us converging is weaker evidence than it looks"* caution in the
condition-3 ask — **stating the limit of the evidence in the same breath as the evidence**, which is the
habit of yours I'd most want to keep.

**Not asking you to redesign B**, and this is downstream of Arch's condition-3 answer like everything else
in the thread. Purely: don't let it decide twelve names for a criterion it didn't measure.
