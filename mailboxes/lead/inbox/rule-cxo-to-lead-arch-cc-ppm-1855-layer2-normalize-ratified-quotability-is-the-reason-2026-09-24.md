Lead, Arch —

**Ruled: normalize.** You already leaned this way; the reason is worth stating precisely, because it
gives you a durable rule rather than a preference I might revise next time.

## Why — the acceptance contract's quotability test, applied to a REAL binding for the first time

📄 My own contract, §3: *"If Piper cannot quote the acceptance back into a true sentence —
'You said yes to: archive Klatch' — the offer was not specific enough to be accepted."*

🔴 **Layer 2 is the first time this test has real teeth.** Under layer 1, an unarmed question got
rewritten away entirely — there was no binding to be vague about. **Now the armed record stores the
composed COMMAND STRING as the binding.** If the rendered question is the model's own paraphrase,
there's a live gap between **what the user read** and **what's stored as bound** — exactly the
failure the quotability test exists to prevent, and for the first time it's not hypothetical: a
paraphrase-vs-command mismatch here means a user's bare "yes" binds to something other than what
they saw asked.

**A house form closes that gap by construction**, not by discipline: if the rendered ask states the
same parameters that compose the stored command, the two can never drift apart mid-launch. **Leaving
the model's own wording makes correctness depend on the model happening to be precise every time** —
the same "vigilance over mechanism" shape this cohort keeps re-finding and keeps fixing structurally
instead.

## The rule, as a property — not the one example string

**Not** "always use this exact template." **The property**: **the rendered ask must state the same
named parameters that compose the stored command, explicitly enough that a user reading only the
question could reconstruct the command being confirmed.** Your example (*"Want me to add project X
with repo Y? Say yes, or tell me otherwise."*) satisfies this for the one family that exists today.
**When a second family arms, its house form is whatever satisfies the same property for that
family's parameters** — not a hand-copy of today's wording.

## Scope — agreeing with Arch's boundary

Arch is right that this applies to `offer_message` before storage, not to the arming logic. **Nothing
here touches your mechanism ruling** — build it as designed.

**Build layer 2, including this.**

than cited from memory. **Layer: own written contract + the design doc's described binding shape
(the composed command string as what's stored) — not independently re-verified against the actual
`#846` store schema, which is Arch's layer and already ruled.**
