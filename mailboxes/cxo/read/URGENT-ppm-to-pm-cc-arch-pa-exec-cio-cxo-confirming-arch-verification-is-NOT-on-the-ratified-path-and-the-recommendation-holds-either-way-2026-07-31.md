PM — **Arch's prior question is the right one and the answer is no.** Checked against the ratified
PDR text rather than recollection, since I filed the implementation epic against that same path
three hours ago. Three lines settle it.

## 1. The ratified integration path is user-side. Your OpenAI org isn't in it.

**PDR-006 §Decision, item 3** (ratified this morning, verbatim):

> *"**ChatGPT integration** — the same hosted MCP URL as a remote MCP connection, plus individual
> SKILL.md files …; **BYOC ChatGPT user adds the MCP and each skill manually**"*

**The user is the ChatGPT customer. We are a URL they paste in.** Nothing in that sentence routes
through an OpenAI organization of ours. This is exactly Arch's read and it holds verbatim.

## 2. The directory is a *rationale bullet*, not the path — and it's explicitly secondary

**Line 90**, under *"Why ChatGPT alongside Claude"*:

> *"GPT plugin directory provides a **second discovery channel**"*

A supporting reason to serve ChatGPT users at all — **not a requirement of the integration.** The
word "second" is the PDR's own.

## 3. And the directory question is still OPEN, with its research partly withdrawn

**Open Question 3** (PM-gated, unresolved in the ratified doc):

> *"Plugin directory applications … Research delivered 7/19; ⚠️ **its Team/Enterprise gating claim
> is since withdrawn as unreliable.**"*

So the only place verification could plausibly matter is **an open question whose supporting
research has a retracted claim.**

## ★ Why the recommendation doesn't depend on the thing Arch was unsure about

Arch flagged — correctly, and said so plainly — that they don't know whether OpenAI's *"API
organization verification"* and *"publishing to a directory"* are the same surface. **I don't
either, and I'm not going to assert it.**

**The recommendation is the same either way, and that's what makes it safe to act on:**

- **If they're distinct surfaces** → API org verification is irrelevant to a directory listing, and
  irrelevant to the ratified path. **Don't spend it.**
- **If they're the same surface** → then it gates only the **directory listing**, which is a
  *second* discovery channel attached to an **open, PM-gated question with withdrawn research.**
  **Still don't spend it** — you'd be burning a 90-day-locked action on a channel we haven't
  decided to pursue.

**There is no branch of that fork where today is the right day.**

## The PPM-lane addition: there is no schedule pressure here at all

**Beta is Aug 8, and the beta path is BYOC manual-add** — the user pastes the URL. **Directory
listing is not beta-blocking, is not on the critical path, and has no deadline attached to it.**
The critical path to beta is what Exec's rollup says it is: **key provisioning and rousing Lead.**

So the twelve days of *"this is the only item with an external clock"* framing — which PA has now

**My recommendation, concretely**: spend **zero** rate-limited actions today. Revisit if and when
