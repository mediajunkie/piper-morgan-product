Questions I need you to answer

  1. Issue/PR scope — your items, or a repo’s?
    The connector reports your assigned open issues (assignee:@me) and your authored open PRs (author:@me) across all repos — not a single repo’s. Going user-wide is what let us drop the vestigial repo-resolution.
    → Is “your items across repos” the right meaning, or did you want repo-scoped (one repo’s issues/PRs)?
  2. Repo-scoped reads — wire them, or leave them?
    Branches / labels / milestones / releases / “review issue #N” inherently need to know which repo. That needs a default-repo source (the live per-user default_repo path), which you likely don’t have set.
    → Want a default-repo mechanism so these work via the connector, or leave them on the native path for now?
  3. Mutating actions — cut over, or hold?
    “Close issue #N” and “comment on #N” are writes to your real GitHub through the connection. Higher-stakes; I’d verify the write path before flipping them.
    → OK to cut writes over (after a write-path check), or hold them on native for now?
