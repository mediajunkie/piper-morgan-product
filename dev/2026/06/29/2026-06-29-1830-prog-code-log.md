### 1. Connector call pattern (mirror target)
`services/mcp/consumer/github_adapter.py`:
- `list_open_issues` / `list_open_prs` → thin wrappers over `_search_via_connector(tool, query, limit)`.
- `_search_via_connector` is the binding-aware honest-degrade rail: no binding → CONNECT_REQUIRED

- `_mcp_client_ctx` yields an MCPClient over `connect_http` with the #358 grant as `Authorization`.
- Result dataclass `GitHubIssuesResult(issues | total | degradation)` — exactly one of issues/degradation.

### 2. github-mcp-server tools (AUTHORITATIVE — from official README, github/github-mcp-server main)
| Read type | Connector tool | Params | Decision |
|---|---|---|---|
| Branches | `list_branches` | owner, repo, page, perPage | **CUT OVER** |
| Labels | `list_label` | owner, repo | **CUT OVER** |

KEY: single-issue read in this server version is the consolidated `issue_read` tool with a
`method` arg (`get`/`get_comments`/...), NOT a `get_issue` tool. Milestones have NO MCP tool
in github-mcp-server → milestones handler must remain native-PAT (do not fake a tool, per prompt).

### 3. Resolver
`services/integrations/github/repo_resolver.py::resolve_repo(user_id=, project_id=, explicit=)` →
`ResolvedRepo(owner, name)` or raises `UnresolvedRepoError`. Repo-scoped reads REQUIRE a repo →
on `UnresolvedRepoError` → honest "which repo?" (never silent-empty / never get-all). Confirmed by
doc-of-record `docs/internal/architecture/current/github-repo-resolution-rules.md` (#1327 gap 2 =
exactly branches/labels/milestones/releases via connector + resolve_repo + honest-degrade on unresolved).

### 4. Handlers to cut over

`_handle_list_releases_query`, `_handle_list_milestones_query`, `_handle_review_issue_query`. They
