## Context

#1331: user asks Piper to perform a WRITE in chat (e.g. "add a milestone to my
default repo"). The LLM classifier recognizes `create_milestone` (free-form
action) but NO handler/WorkflowEntry exists → the action falls through to the
floor (the LLM), which CONFABULATES "Milestone created ✓" with full details — no
actual GitHub write. Trust-property violation.

Fix scope: honest-degrade FLOOR only. Unwired write actions must decline honestly
("I can't create milestones from chat yet") via a WorkflowEntry + handler on the

## Investigation (verify-before-extend)

- `llm_classifier.py:537` regex fallback recognizes: `create_issue`,
  `list_projects`, `update_status`, `generate_report`, `create_milestone`.
- Classifier prompt (`_build_classification_prompt`): free-form `action` field +
  verb vocab. Verb enum has NO `create` verb → create-requests emit free-form
  action like `create_milestone`. The shim returns None → free-form action kept.
- Dispatch flow (`process_intent` ~line 1451): action-dispatch rail
  (`if intent.action in get_action_workflows()`) runs BEFORE category routing —
  so a WorkflowEntry keyed on the action intercepts it regardless of category.
- Confabulation mechanism: `create_milestone` has no handler → (whether classed
  EXECUTION → graceful `else` → ConversationalFloor, or any other category →
  floor) it reaches the floor. Floor system prompt forbids fabricating user DATA
  (todos/issues/projects) but NOT fabricating action SUCCESS → "Milestone
  created ✓".
- WIRED writes (NOT the bug, left alone): `create_issue`/`create_ticket` →
  `_handle_create_issue` (real handler, errors honestly on dead PAT);
  `update_issue` → `_handle_update_issue`; `generate_report` → ANALYSIS cohort
  `_handle_generate_report`; close/reopen/comment → #1124 WorkflowEntries
  (honest errors). `complete_todo`/`create_todo`/`create_reminder` → todo handlers.
- UNWIRED writes (the bug, FIXED): `create_milestone` (confirmed), plus
  reliably-classifiable create-write siblings with no handler: `create_release`,
  `create_label`, `create_branch`, `create_pull_request`. `update_status` is
  ambiguous (no handler, but vague) — covered defensively.
