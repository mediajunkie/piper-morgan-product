### Finding 2 — the "unexplained hook intermittency" in CLAUDE.md is explained; it's command shape, not time

Orientation said to expect a PASS and **escalate loudly on disagreement**. I got a
disagreement, chased it, and it resolved into a reproducible mechanism.

**Probe series** (all on `claude/web-cycle`, staging a file under `mailboxes/`):

| # | Shape | Index state when hook fired | Result |
|---|---|---|---|
| 1 | `git add X && git commit` (one Bash call) | empty | **NOT blocked** — commit succeeded |
| 2 | `git add X` (call A), then `git commit` (call B) | X staged | **BLOCKED**, names `check-branch.sh` |
| 3 | `git add Y && git commit` (one call), probe-2 file still staged | Y' staged from before | **BLOCKED** |
| 4 | `git add X && git commit` (one call), index verified empty first | empty | **NOT blocked** |

**Mechanism**: `check-branch.sh:28` decides via `git diff --cached --name-only`.
PreToolUse fires **before** the Bash call executes — so for a compound
`git add … && git commit …`, *the `git add` has not run yet* and the index is
empty at hook time. The hook inspects an index that does not yet contain the
files being committed, finds no `mailboxes/` paths, and exits 0.

**This is deterministic by command shape**, 2/2 in each direction — not the
hours-timescale randomness CLAUDE.md currently describes as "real, unexplained."
It also retro-explains CIO's 1-of-5-then-4-of-4 pattern without needing an
intermittency: whether a probe blocks depends on whether mailbox paths happened
to be staged *before* the probe's own call began.

**Confirming details**: block surfaced as `PreToolUse:Bash hook error:
[bash .claude/hooks/check-branch.sh]: No stderr output` — exactly the signature
CLAUDE.md documents as *the hook working*. The path is **relative**, so the
**project layer** caught it (user layer uses absolute paths). Config verified
correct and script present+executable at both layers before probing, so this is
not config drift.

**Consequence, and why it matters more than the diagnosis**: the near-universal
agent idiom is `git add … && git commit …` in one Bash call. That is precisely
the shape the hook cannot see. So the mailbox backstop has been **silently
absent for the common case** — while the 2026-07-25 verification, which used a
staged-first shape, correctly reported PASS. Both results were true; they tested
different things. This is the CLAUDE.md rule about verifying behaviorally biting
one level deeper: *the probe's shape has to match the shape you actually use.*

All four probes fully reverted — index clean, `git status` empty, HEAD back at
`a1763a236`, 0 ahead of `origin/main`, no probe files on disk. Cleanup used
`git reset` (soft) + explicit-path `rm`, never a broad discard.
