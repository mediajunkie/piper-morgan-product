### 18:30 — Web found the mechanism. My n=2 claim withdrawn.

Web's memo (18:05) identifies the real cause, and it's predictive rather than descriptive:
**`check-branch.sh:28` decides via `git diff --cached --name-only`, and PreToolUse fires
BEFORE the Bash call executes.** So in the near-universal idiom `git add <path> && git
commit …` — one Bash call — the `git add` has not run when the hook inspects the index. The
hook sees an empty index, finds nothing under `mailboxes/`, exits 0, and the commit
proceeds. Whether a probe blocks depends entirely on **index state at hook-fire time**.

**Verified the confound in my own transcript rather than accepting it on assertion:**
- Probe 2 staged the file in a **separate** Bash call, which ended
  `git status --short mailboxes/` → `A  mailboxes/ppm/inbox/.hook-probe-ppm.md`.
- Probe 2's commit was **BLOCKED → never ran → file never unstaged.**
- **Probe 3 therefore fired against an already-dirty index**, independent of its own
  `git add`. It could not distinguish anything.

I designed probe 3 as the decisive controlled repeat of probe 1. It wasn't one. All three
of my rows are predicted by Web's mechanism; none needs lazy-attach. The same confound
propagates to PA's probe 4 (PA's probe 3 also blocked → dirty index), which was the
strongest support for the hypothesis.

**What I actually got wrong**: not the probing — running probes and reporting the fail
loudly was right. The error was **treating "command shape" as the only variable I'd changed
between probes, when I'd also changed index state without noticing.** Web printed
`git diff --cached --name-only` before and after every step; that single habit is the whole
difference between the two datasets. Adopting it.

**The second-order lesson, which is the more dangerous one**: PA and I produced matching
tables independently and read the agreement as corroboration. It wasn't — we'd both
inherited the same confound from the same natural probe sequence (probe, then re-probe
without clearing). **Independent agents converging on the same wrong answer via the same
unexamined default looks exactly like replication.** Agreement between agents running the
same procedure is much weaker evidence than it feels like.

Also conceded: my 13:05 argument that user/project layer alternation is a *diagnostic
signal* — Web's reading is that it's reporting noise. The don't-consolidate-the-layers
advice still stands, but on general caution, not on alternation being informative.

**Operative consequence, and it's the part that matters**: the 7/25 verification that turned
this hook green was a *staged-first* probe. Agents overwhelmingly write `git add … &&
git commit …` in one call. **So the mailbox backstop has been silently absent for the common
case while reporting green** — both results true, testing different shapes. Until fixed,
**stage in one call, commit in the next**; that's the shape the hook can see. Doing that.

Correction memo sent to Web + CIO + PA (cc PM, HOST, Exec) — commit `f55041a33`.
