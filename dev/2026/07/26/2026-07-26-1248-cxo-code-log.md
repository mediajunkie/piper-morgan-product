## ⚠️ FINDING — hook bypass is reproducible on my seat, and the discriminator is COMPOUND vs STANDALONE

**My single probe-1 PASS above was wrong to rest on.** PA filed a fresh-seat bypass counterexample
today (`1a87c2dde`, 13:15 PT) while I was working. I read it before reporting and ran four more
probes. On my seat the result is **not intermittent — it is a clean, reproducible discriminator**:

| # | Command shape | Message | Result | Layer named |
|---|---|---|---|---|
| 1 | **standalone** `git commit` | plain | **BLOCK** | project (relative path) |
| 2 | **compound** `echo && add && commit` | `$(date +%s)` | **BYPASS** | — |
| 3 | **compound** (identical to #2) | `$(date +%s)` | **BYPASS** | — |
| 4 | **compound** | plain, no substitution | **BYPASS** | — |
| 5 | **standalone** `git commit` | plain | **BLOCK** | **user (absolute path)** |

**Standalone: 2/2 BLOCK. Compound: 3/3 BYPASS.** Five probes, one seat, ~4 minutes, no config change.

**What this establishes and what it doesn't:**

1. **Command substitution is excluded** — probe 4 (compound, plain, no `$(...)`) bypassed anyway.
   Confirms PA's exclusion by a different route.
2. **The live variable on my seat is compound-vs-standalone**, which PA's probe set did *not*
   isolate — PA's probe 3 was "compound, plain → BLOCK," the **direct opposite of my probe 4**.
   So this is **not** a universal law either; PA's seat and mine disagree on the same shape. What
   I can say is that on my seat it is 5/5 consistent and *reproducible on demand*, which is a
   stronger handle than "intermittent" and worth someone testing on a third seat.
3. **Both hook layers are live on my seat and they alternate** — probe 1 caught by the *project*
   layer (relative path), probe 5 by the *user* layer (absolute path). Independently reproduces
   CIO's 22:39 finding on 7/25 and re-confirms **do not consolidate the two layers.**

**The practical bite, and why this isn't academic**: `git add <paths> && git commit -m …` is the
compound shape — **it is how essentially every agent in this cohort commits, including both of my
own real commits earlier in this session.** Those were never hook-checked. So the mailbox-discipline
backstop is bypassed *by exactly the command form in routine use*, while a rarely-used standalone
form is the one that gets caught. That inverts the coverage assumption: the hook looks alive
whenever you test it deliberately in the unusual shape, and is absent during ordinary work.

**Operative stance for me**: treat the hook as **not covering me**, enforce mailbox discipline and
log maintenance by prose (mail via `scripts/mail-send.sh` push-to-ref regardless), and say so in
fire entries. This is consistent with the standing rule that the hook is **advisory, not a
control** — `git -c` and `--no-verify` bypass it by design — but the cohort has been treating it as
a net, and on the common command shape it is not one.

All five probes cleaned up: files deleted, commits reset (`--mixed`, never `--hard`), working tree
clean, branch level with `origin/main`, zero residue in `mailboxes/`.
