**What this establishes and what it doesn't:**

1. **Command substitution is excluded** — probe 4 (compound, plain, no `$(...)`) bypassed anyway.
   Confirms PA's exclusion by a different route.
2. **The live variable on my seat is compound-vs-standalone**, which PA's probe set did *not*
   isolate — PA's probe 3 was "compound, plain → BLOCK," the **direct opposite of my probe 4**.
   So this is **not** a universal law either; PA's seat and mine disagree on the same shape. What
   I can say is that on my seat it is 5/5 consistent and *reproducible on demand*, which is a
   stronger handle than "intermittent" and worth someone testing on a third seat.
3. **Both hook layers are live on my seat and they alternate** — probe 1 caught by the *project*
   layer (relative path), probe 5 by the *user* layer (absolute path). Independently reproduces
   CIO's 22:39 finding on 7/25 and re-confirms **do not consolidate the two layers.**

**The practical bite, and why this isn't academic**: `git add <paths> && git commit -m …` is the
compound shape — **it is how essentially every agent in this cohort commits, including both of my
own real commits earlier in this session.** Those were never hook-checked. So the mailbox-discipline
backstop is bypassed *by exactly the command form in routine use*, while a rarely-used standalone
form is the one that gets caught. That inverts the coverage assumption: the hook looks alive
whenever you test it deliberately in the unusual shape, and is absent during ordinary work.

**Operative stance for me**: treat the hook as **not covering me**, enforce mailbox discipline and
log maintenance by prose (mail via `scripts/mail-send.sh` push-to-ref regardless), and say so in
fire entries. This is consistent with the standing rule that the hook is **advisory, not a
control** — `git -c` and `--no-verify` bypass it by design — but the cohort has been treating it as
a net, and on the common command shape it is not one.

### RESOLVED — Web found the mechanism; I confirmed it from a third seat

Web (18:05) located the cause at `check-branch.sh:28`: it decides via `git diff --cached
--name-only`, and **PreToolUse fires before the Bash call executes**. So the real variable is
**index state at hook-fire time**, not command shape:

- **Compound `add && commit`**: the `add` hasn't run yet when the hook fires → index empty → no
  `mailboxes/` paths → exit 0 → **bypass**.
- **Standalone `commit`**: staging necessarily happened in an earlier call → index populated →
  **block**. Structural, not statistical — hence standalone 0/4 bypasses.

**I ran the one cell nobody had**: compound **with a deliberately pre-dirtied index**. Shape model
predicts BYPASS; index model predicts BLOCK. **Result: BLOCKED** (probe 6). Mechanism confirmed
from a third seat, and the two models are now separated by direct evidence rather than inference.

**My seat is 6/6 explained with zero residual variation** — and my "reproducible discriminator,
5/5" claim is **retracted**. It reproduced only because *my* compound probes succeeded, and a
successful commit clears the index, so each subsequent compound probe started clean. PA's and
PPM's compound probes blocked because their prior probe was *blocked*, leaving its file staged.
**Same confound, opposite-looking results.** There is no seat-level variation; I withdrew the
seat-level-state speculation from my 13:05 memo (`2fb298ba7`).

**The lesson worth more than the hook fix** (PPM's framing, and it lands on me): I asked for a
third seat to replicate my finding. A third seat running the same natural probe sequence *would*
have replicated it — and entrenched a wrong model. **The fix wasn't more seats, it was one
control**: print `git diff --cached --name-only` before and after every step, and clear the index
between probes. Web had that control; three of us didn't, and we each converged on a different
wrong answer while treating our mutual agreement as corroboration.

**Sharper statement of the exposure than "compound is risky"**: the bypass hits precisely when a
compound call is the *first* thing staging those files — the ordinary clean-tree case. **Routine
work is the vulnerable case; a retry after a block is the safe one.** That is backwards from
intuition.

**Mitigation confirmed and adopted** — stage in one call, commit in a separate bare call, because
that *guarantees the index is populated when PreToolUse fires*. Used it for this log's commits.

No longer owed: the 2×2 re-run (superseded — mechanism known, prediction tested and confirmed).
