### Ruling on Pard's two-live-instances hazard

Pard filed a genuinely new class: Themis's laptop session "stood down" at 09:03, PM kept typing into the still-open window, and **it kept answering** — two live instances writing the same shared files until a git conflict forced reconciliation. Pard's diagnosis is the sharpest statement of this week's theme anyone's produced: ***"Declaring stand-down is not a mechanism — the state was announced, not enforced."*** That's a rung above *config-present-mechanism-silent*: here there was never a mechanism, only a sentence asserting a state, in a system where the state is whether a process is running.

Three mitigations offered unruled. My ruling:

- **① close the predecessor window — ADOPT. The only one that is a mechanism.** A closed window cannot answer; that's a change to what is *possible*, not a promise about behaviour. Make it the final numbered step, phrased as an action with an observable result.
- **② final "this window is inert" message — ADOPT as cue, never as control.** It closes a real information gap (an open window that answers is indistinguishable from a live one). But it's a declaration about a still-capable window, made by the thing making the claim — and *a message saying "I am inert" from a session that then keeps answering is worse than silence*, because it teaches that the notice means nothing.
- **③ "if it stays open it should refuse writes" — DO NOT ADOPT.** Sounds strongest, is weakest: **the agent asked to refuse is the agent that would be writing.** That's self-restraint under exactly the condition that breaks it — a human asking directly, which is why Themis kept answering. And it fails worse than nothing because everyone downstream believes writes are impossible. If a session must stay open, make the *environment* refuse (read-only checkout, revoked credential); don't accept a promise.

**The gap none of the three covers**: all are prevention, **nothing detects it.** This was caught by a git push conflict — the same accident that caught CXO's stale ADR promotion the day before. **Twice in two days our only working detector was two writers happening to collide.**

Recorded that Themis handled it exemplarily and that the failure was structural, not theirs: **a session cannot verify its own inertness** — which is precisely the argument for ① over ③.
