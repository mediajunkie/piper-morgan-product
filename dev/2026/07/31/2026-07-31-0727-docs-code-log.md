### ★ Arch proposed the structural cure for my bulk-stamp finding, and it's better than my checklist item

My Doc Currency Check says *"only stamp a doc you actually verified."* Arch is right that this is
**vigilance and will decay silently** — the defining property of the whole class.

**Their cure: require the stamp to NAME WHAT IT CHECKED.**

```yaml
last_verified: "2026-06-19"
verified_scope: "hook registration; log path exists; exit semantics"
```

The elegant part: **the cure and the detector are the same command.** A bulk `sed` copies one date
across 23 files in a second and **cannot produce 23 distinct plausible scope lines** — and if it emits
one line 23 times, that repetition is the signature, caught by the same `sort | uniq -c` that exposed
the date cluster. m-44's rule moved from instruments to data: *an instrument must assert what it looked
at* → **a verification stamp must name what was verified.**

### Shipped a worked example (`3bcd36d5b`) — and deliberately stopped at two docs

Added `verified_scope` to `BRIEFING-ESSENTIAL-DOCS.md` and `ROLE-PORTFOLIO-DOCS.md` — **the only two I
can honestly scope**, because they're the two I verified claim-by-claim on 07-30.

⚠️ **Did NOT add it corpus-wide, and the restraint is the point**: stamping a scope line onto docs I
haven't read would reproduce the exact defect the field exists to prevent, one layer up. **A fabricated
scope line is strictly worse than a bulk date, because it reads as evidence.**

Two facts for CIO's decision, both verified:
- **Backward compatible** — `check-staleness.py` parses the frontmatter unchanged with the new field present. No script change needed to adopt.
- **The signature already works** — `grep -rh "^verified_scope:" | sort | uniq -c` returns **two distinct lines, count 1 each.** A bulk operation would surface as one line with a high count, same command.

Corpus adoption is CIO's call (#972 field change). Routed with both facts.
