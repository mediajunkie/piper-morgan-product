### Finding 1 (material) — the memory symlink is on the wrong key, and the premise underneath it looks wrong too

Pard wired: `~/.claude-pm/projects/-Users-xian-Development-piper-morgan-worktrees-cio/memory` → `~/.claude-pm/pm-shared-memory`. That symlink exists and is correct-looking.

**But it is not the directory this session's memory actually resolves to.** The harness reports my memory directory as:

```
/Users/xian/.claude-pm/projects/-Users-xian-Development-piper-morgan-product/memory/
```

— keyed to the **main repo root**, not to my worktree path. That directory is a plain directory (not a symlink), and it is **empty**. Evidence:

```
~/.claude-pm/projects/
  -Users-xian-Development-piper-morgan-worktrees-cio/   ← session transcript .jsonl + Pard's symlink
  -Users-xian-Development-piper-morgan-product/          ← ONLY memory/ (empty), created at session start 10:48
```

`git rev-parse --git-common-dir` → `/Users/xian/Development/piper-morgan-product/.git`. So transcripts key on **cwd**; memory keys on the **git common dir**. Pard symlinked the path Claude Code was expected to use; Claude Code used a different one. The symlink is currently a no-op.

**The good news, if it generalizes**: git worktrees off one repo would then share ONE memory key *by construction* — no symlink needed at all, and the silent-split failure mode we designed around doesn't exist for worktrees.

**The premise it rests on also appears to be a misidentification.** Pard's empirical proof for the split was "Vergil's `openlaws-ra-main` worktrees each already carry their own memory key." But `/Users/xian/Development/openlaws-ra-main/.git` is a **directory**, not a gitfile — it is a separate *clone*, not a worktree. Separate clones obviously get separate keys; that observation doesn't bear on worktrees.

**Holding this as one data point, not a conclusion.** I have exactly one worktree to observe, and the memory export's own `feedback_surface_files_via_senduserfile_not_paths` pin is a standing warning about asserting a mechanism from a single observation against a client that ships updates faster than daily. The decisive test is the *second* agent's worktree: if it also resolves to `-piper-morgan-product`, memory is shared by construction and the symlink layer can be dropped. That test costs Pard about a minute and should happen before the cohort migrates.
