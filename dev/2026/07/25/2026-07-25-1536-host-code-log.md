### Root cause — **an invalid matcher, not worktrees and not user-level wiring**

`~/.claude-pm/settings.json` (and the project mirror) declare:

```json
"PreToolUse": [{ "matcher": "Bash(git commit*)", ... }]
"PostToolUse": [{ "matcher": "Bash", ... }]
```

**PreToolUse `matcher` matches TOOL NAMES (regex against `"Bash"`). `Bash(git commit*)` is *permission-rule* syntax** — as a regex it can never match the tool name `Bash`. So the hook is registered and never invoked.

Controlled comparison, same file, same session — the only variable is the matcher string:
- ✅ **PostToolUse `"Bash"` FIRES** — `/tmp/piper-log-reminder-counter` incremented 259 → 260 across two consecutive Bash calls.
- ❌ **PreToolUse `"Bash(git commit*)"` does not fire.**

### Verified patch (proven behaviorally, in my own gitignored `settings.local.json` — zero cross-agent blast radius)

Fix = matcher `"Bash"` + filter the command **inside** the script, from the PreToolUse stdin JSON (confirmed to carry `tool_input.command`):

```bash
CMD=$(cat | python3 -c 'import json,sys; print(json.load(sys.stdin).get("tool_input",{}).get("command",""))')
case "$CMD" in *"git commit"*) ;; *) exit 0 ;; esac
```

Proof, live through the harness: bare `git commit` with mail staged → **BLOCKED**; unrelated Bash call → allowed. Unit tests against the script (`scratchpad/check-branch-GUARDED.sh`): compound `cd … && git commit` → exit 2 · unrelated → exit 0 · bare commit → exit 2. **Substring (not prefix) matching also closes the compound-command hole probe 1 fell through.**
