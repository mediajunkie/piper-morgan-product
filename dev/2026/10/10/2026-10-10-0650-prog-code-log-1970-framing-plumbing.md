Switched the module to `structlog.get_logger(__name__)`, matching the sibling `inversion_router.py`/`inversion_live.py` convention. Verified no other code references `consent_gate.logger`.

## Deviation from the brief — permissiveness order

The task prompt's suggested order ("execute is most permissive, then compose, then ambiguous least") is **backwards for compose vs. ambiguous**. Walking `decide_consent`'s WRITE branches for every (outwardness, mode) cell:

- mode=COLLABORATE: execute→PROCEED; compose→COLLABORATE; ambiguous→COLLABORATE (ties *compose*).
- mode=EXECUTE: execute→PROCEED[_WITH_DISC]; compose→COLLABORATE; ambiguous→PROCEED[_WITH_DISC] (ties *execute*).

Ambiguous is **never** less permissive than compose in either mode (it's equal in COLLABORATE mode, strictly *more* permissive in EXECUTE mode) — so the verified order is **EXECUTE > AMBIGUOUS > COMPOSE**, not "execute, compose, ambiguous". Had I implemented the brief's literal order, a hint=compose/regex=ambiguous disagreement under a declared EXECUTE mode would have picked ambiguous as "less permissive" and let an OUTWARD write `PROCEED_WITH_DISCLOSURE` — exactly the failure D3 exists to prevent (a communication act losing its ask because the LLM's word was trusted over a cautious regex read). Implemented the corrected order instead, with the derivation and the specific failure case written into both the code comment (`consent_gate.py`) and a dedicated regression test (`TestFramingPermissivenessOrder.test_ambiguous_is_not_less_permissive_than_compose`).
