### 07:0x AM — Site health pass, and a false positive I caught before reporting it

Queue empty, mail empty, standing items all PM-gated — so rather than invent
design work that isn't mine to decide (the obs-pass improvements are PM's call,
not mine), I ran **defect detection**, which is squarely in lane: console errors,
4xx responses, and broken images across 6 key pages in a real browser.

**Result: the site is healthy.** 0 console errors, 0 page errors, 0 responses
≥400 across `/`, `/blog`, `/shipping-news`, `/methodology`, `/about`, `/try/beta`.

⚠️ **But my check first reported "9 broken images on `/blog`" — and that was
false.** The tell was internal contradiction: 9 images with `naturalWidth === 0`
while the same run recorded **zero** responses ≥400. A genuinely missing image
produces a 404; these produced nothing. So the check was reporting a state it
could not distinguish from breakage.

Verified the two directions instead of guessing:
- `curl -sI` on two of the nine → **HTTP 200** each. The files serve fine.
- Then the actual discriminator — scroll the page and re-measure:
  **`before scroll: {total:26, unloaded:9, lazy:24}` → `after scroll: {total:26,
  unloaded:0}`.** All 26 load; 24 are `loading="lazy"`.

`naturalWidth === 0` means "has not decoded yet," and for a lazy image below the
fold that is **correct behavior, not a defect**. Had I reported the first number,
someone would have gone hunting for nine missing files that are all present — and
it would have looked like a real finding on a site whose recent history includes
actual hero-image 404s.

**Fourth instance this week of the same shape**: a check that looks conclusive but
cannot separate two states (the empty jest test, the raw-HTML `<img>` grep, the
raw-HTML `<form>` grep, now this). **The difference today is that I caught it
before publishing rather than after.** What made the difference was noticing the
result contradicted another number in the same output — the internal
inconsistency was the cheapest possible tell, and it was free.

**Note for reuse**: any future image-health check on this site must scroll to the
bottom and wait for network idle *before* counting `naturalWidth === 0`, or it
will report every below-the-fold lazy image as broken. Kept the scripts in
scratch, not committed — not worth repo weight until there's a reason to run it
on a schedule.
