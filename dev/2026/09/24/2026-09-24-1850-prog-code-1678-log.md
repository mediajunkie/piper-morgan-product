**Issue**: #1678 — PIPER.md content never reaches the system prompt

## Task

`PiperConfigLoader._format_system_prompt()` extracted six hardcoded section
names from an old PIPER.md layout, none of which exist in the current
v3.0.0 file — so the curated file's entire content was silently dropped
and only two scaffold lines + a hardcoded BEHAVIOR GUIDELINES block ever
reached the LLM.

   Conversational Strengths`, `🔐 Privacy & Data Handling`, `📝

## Fix

`services/configuration/piper_config_loader.py::_format_system_prompt`
(and new helper `_clean_section_header`, staticmethod): renders **every**
section the parsed config actually has, in file order, instead of matching
against the stale six-name list. Header rendering strips a leading
emoji/symbol (`^[^\w(]+`) then uppercases — this is byte-identical to the
old hardcoded output for plain keys like `"User Context"` →
`"## USER CONTEXT"` (verified: `NEUTRAL_DEFAULT_CONTEXT` renders
byte-identical to the pre-fix hardcoded path, pinned by test).
BEHAVIOR GUIDELINES stays unconditionally appended — PIPER.md's "Default
Personality Traits" section overlaps in spirit but is not a strict
superset (no "use the user's name" / "suggest next steps" equivalent), so
dropping the hardcoded block would lose guidance, which #1678 rules out.
Honest-empty behavior for missing/unparseable files was already correct
(`load_config()` logs a warning and falls back to `_get_default_config()`)
— untouched, and now covered by dedicated tests.

## #1655 prompt-hygiene check on newly-live content

Reviewed all 10 sections for the #1655 hazard class (literal example REPLY
sentences that get parroted/fabricated verbatim). Findings:
- `🆘 Fallback Behaviors` already carries an explicit #1655 note in its own
  text ("stated as a rule, never as a scripted reply sentence; see #1655")
  — this section was already hygiene-swept during the #1655 sweep, even
  though it was latent (not live) at the time; #1678's own text confirms
  this ("the #1655 sweep initially misjudged a PIPER.md example sentence
  as a live hazard until this was checked — it is latent, not live").
- `📖 Usage Examples` uses a `"user query" → capability description` arrow
  format (e.g. `"Create an issue for bug X" → Creates GitHub issue`) —
  these describe WHAT Piper does, not literal words Piper would say; read
  as the issue's own "context-line examples are fine" category, not the
  "reply-sentence examples" hazard.
- No other section contains example dialogue or scripted reply text.
- **Discovered, not fixed** (out of my scope — I own the loader, not
  PIPER.md content curation): `🔐 Privacy & Data Handling`, `📝
  Configuration Management`, `🚀 System Performance` are meta/internal
  documentation (bcrypt/JWT internals, cache TTLs, latency targets) that
  will now reach the live LLM system prompt verbatim. Not a #1655 hazard
  (no reply-sentence content) and not incorrect, but it's prompt-token
  noise arguably irrelevant to conversational assistance — a candidate for
  a future PIPER.md content-curation pass, not something I'm fixing here.
- **Discovered, not fixed**: `config/PIPER.user.md.example`'s `PM
  Identity` / `GitHub Integration` sections mix a YAML config block with
  prose instructions. If an operator's real (gitignored) `PIPER.user.md`
  keeps that shape, those YAML blocks will now reach that principal's own
  system prompt too (never cross-user, per ADR-075 D3/D4 — this only
  affects the file's own owner). No such section exists in the currently
  tracked `config/PIPER.md`, so this doesn't affect the default/shared
  path today. Flagging as a possible future "not-for-prompt" convention
  rather than inventing one unilaterally, since none exists today and the
  issue explicitly said to respect an existing convention, not create one.
