### Fire 3 (17:40-18:05) — the fix, and one real break in the proposed design

Built: `IntentService._is_orchestratable_sibling` (the single path's predicate pair,
in its order) + a partition in the multi-intent branch. Orchestrate only when the
floor-routed partition is empty and ≥2 substantive siblings remain; otherwise skip

⚠️ **The Lead's proposed skip ("choose a floor-routed sibling") is wrong for one
real class, found by an existing ratchet, not by inspection.**
`tests/unit/services/intent_service/test_spend_free_canonical_ratchet_1818.py`
went red on `("PORTFOLIO", "manage_portfolio")`. Probing the premise:

```
'archive project X in my portfolio'  is_multi: True
    PORTFOLIO manage_portfolio
    STATUS    get_project_status      <- PHANTOM, the #1738 class
```

The plain one-topic archive command is split by the pre-classifier into PORTFOLIO
plus a phantom STATUS sibling — #1738's `_apply_subsumption_filter` covers only the
LIST claim, not archive/add/delete phrasings. So at HEAD this command already earns
the false retry rider (a SECOND live occasion for #1763 beyond the list phrasing),
and under the naive skip it would have stopped performing the archive AND started
billing a keyless turn. Fix: a side-effecting orchestratable sibling
(PORTFOLIO/EXECUTION — the two categories `_requires_canonical_handler` treats as
unconditionally canonical *because* they have side effects) wins the skip; otherwise
the first floor-routed sibling. Pinned in `TestSkipPreservesSideEffectingSiblings`,
premise included.

Residual, stated: a genuinely two-topic turn naming both a write and a floor topic
answers the write only. Strictly narrower than HEAD (same omission, minus the false
promise); answering both needs a floor leg in the orchestrator — out of scope.
