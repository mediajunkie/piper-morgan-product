### Item 2 — UserAPIKeyService bool-swallowing
- Grepped all callers of `validate_user_key`/`rotate_user_key`: `web/api/routes/api_keys.py:331` (`POST /keys/{provider}/validate`), `cli/commands/keys.py:219`, `scripts/status_checker.py:114` — all three consume a bare bool via `is_valid = await ...`, none inspect a richer return.
- `validate_user_key()`: now calls `validate_api_key_detailed()` + `humanize_validation_result()`; **keeps returning bool** (compat); message exposed via a transient `.validation_message` attribute on the `UserAPIKey` row, same pattern as `store_user_key`.
  - **Discovered and documented a real fragility**: unlike `store_user_key` (which hands its caller the SAME object it annotated), `validate_user_key` returns a bare bool — a caller who re-queries the DB *without holding a live reference in between* may get a freshly-hydrated ORM instance without the attribute, because SQLAlchemy's identity map holds objects by weak reference and an unreferenced instance can be GC'd between calls. Confirmed empirically (a naive "call then fresh-query" test failed; holding the reference from `store_user_key`'s return fixed it). Documented in the method's docstring and the test file's docstring so a future caller doesn't get burned by it.
- `rotate_user_key()`: already returned the `UserAPIKey` record (no bool-compat concern). Now raises `ValueError(<honest message>)` instead of the old flat "New API key validation failed for {provider}" — mirrors `store_user_key(store=False)`. Added `except ValueError: raise` before the broad `except Exception` so the honest message isn't re-wrapped.
- Updated the one existing test that broke (`test_validate_user_key_per_user` in `tests/security/test_user_api_key_service.py`) — it patched the old bare-bool `validate_api_key`; now patches `validate_api_key_detailed` returning a `ValidationResult`.
- Fixed `tests/security/integration_test_api_key_audit_logging.py`'s `MockLLMConfigService` (a standalone script, not pytest-collected — `pytest.ini`'s `python_files = test_*.py` excludes `integration_test_*.py`) — added `validate_api_key_detailed` so it doesn't AttributeError if ever run manually.
