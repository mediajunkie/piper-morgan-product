## Fix design

1. `FileResolver` (`services/file_context/file_resolver.py`):
   - Promoted the inline temporal-pattern list to a module constant
     (`_TEMPORAL_PATTERNS`) and added `is_temporal_reference(message)` as a public
     staticmethod — single source of truth, reused by the rail so it never
     re-derives/duplicates the regex.
   - Added stated-distance parsing (`_STATED_DISTANCE_PATTERNS` +
     `_STATED_DISTANCE_N_RE`) and `temporal_window_days(message) -> int` (public
     staticmethod, default 7 when no distance is stated) — "last month"/"a month
     ago" → 30, "last year"/"a year ago" → 365, "yesterday" → 1, "N
     days/weeks/months/years ago" → N × unit-days. `resolve_file_reference`'s
     temporal branch now calls this instead of hardcoding `days=7`, so a stated
     distance widens the window to THAT distance (never silently to something
     wider or narrower than what the user said).
   - Added `list_owner_documents(owner_id, limit=100)` — owner-scoped, NOT
     time-bound (reuses `FileRepository.get_files_for_session`, which despite its
     name is owner-scoped and unbounded by time — confirmed by reading it — plus
     `_artifact_candidates` with `days=None`), most-recent-first. This is the
     fallback set for the naming reply; it is a NEW query, not a widening of the
     temporal query, so 'yesterday' never silently binds to a year-old file.

2. Rail reply site (`run_summarize_document_workflow` in
   `services/intent_service/workflow_entries.py`): when resolution comes back with
   no `file_id` AND the message is temporal-shaped (`FileResolver.is_temporal_reference`)
   AND the account has documents outside that window (`list_owner_documents`
   non-empty), reply names what exists instead of the flat honest-empty — bounded
   render (PPM's `REMAINDER_OFFER_THRESHOLD` = render all ≤3; above that, a capped
   list with an honest "N of M" count, never "and N more" — this site has no
   `self`/session to arm a cashable #1762 remainder, confirmed by grep, so it never
   promises a "show me the rest" it can't cash). Marked
   `# CXO copy pass pending (#1661)` at the new copy. When the account truly has
   ZERO documents (not just outside the window), the original honest-empty reply is
   unchanged — that one is true.

that far (vs. the pre-fix flat empty) is the proof the widening worked.

**Test-mocking gotcha found and fixed**: `test_summarize_document_rail_1624.py` and
`test_summarize_files_view_1657.py` both `patch("services.file_context.file_resolver.

this is the only place in the tree that mocks the whole `FileResolver` class
