### A real mypy [misc] bug caught by the ratchet, fixed

Both `RadarFeed.assemble` and `StandupAssembler.assemble` reuse `e` later in the same function
as a plain for-loop variable over `RadarEntity` (`for e in observed: ...`). My first pass used
`except EntitySourceReadFailed as e:` for the new branch, which collided: mypy's gate (run under
`venv-mypy-gate/`, per `scripts/run-sweep.sh ratchets`) flagged 5 new `[misc]` errors per file
("Assignment to variable e outside except: block" / "Trying to read deleted variable e") —
Python's `except X as e:` implicitly deletes `e` at the end of the handler, and mypy correctly
treats the later loop reuse as reading a deleted name. Renamed both to `err`. Re-ran the gate:
misc back to the ceiling (77), all 24 ratcheted codes at ceiling.
