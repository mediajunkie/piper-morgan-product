Traced why: at ARM time (`_handle_create_issue`'s #1510 gate-held branch) `_gate_subject` comes

populated from a slash-form match — never from a bare name — so nothing was available to strip
against.

Also traced the FILE-time path (`strip_repo_phrase_for(title, repository)` at
`services/intent/intent_service.py:10579`, run after `repository` resolves) to establish what's
actually filed vs. what's shown mid-conversation:
- When the resolved `repository` happens to share a bare name with the phrase (e.g. the user's
  configured DEFAULT repo is `mediajunkie/test-piper-morgan`, matching PM's own test-repo
  convention), the FILE-time strip already fires correctly — confirmed via a second repro:
  `create_issue` called with `title='the login bug'` (stripped), even though the ARMED subject
  upstream was still dirty. This is the scope the 2026-08-29 issue note calls "fixed+pinned."
- When no default repo is configured at all, the file-time path fails to resolve `repository`
  entirely (`extract_natural_repo_name` doesn't recognize the bare form either — same gap, no
  "repository" word) and returns the honest "I couldn't tell which repository" ask. That's a
  wider, pre-existing extraction gap, not something #1695 introduces or is scoped to fix — I left
  it alone and pinned it explicitly as "leave untouched" in the new test (see below).

So the concrete, in-scope bug is specifically the mid-conversation ARMED preview text (and the
offer's stored `draft.title` / `intent.context["title"]`), independent of whatever eventually
gets filed.

## Fix chosen: arm-time resolve-or-strip

**Seam**: `services/intent/intent_service.py`, `_handle_create_issue`'s #1510 gate-held branch,
immediately after `_gate_repo` is computed (one new hunk, ~36 lines, no other code moved).

**Why arm-time over file-time**: file-time (`strip_repo_phrase_for` at line 10579) already runs
and is correct for what gets filed — it just runs too late to fix what the user is SHOWN while the
draft is being negotiated. Only an arm-time fix touches the actually-broken surface (the echoed
preview + the stored offer).

**Why this doesn't violate "drafting needs no connector"**: the resolver added is
`get_user_default_repo` (`services/integrations/github/repo_resolver.py`) — a DB read via
`ConnectorConfigService`, wrapped in its own try/except returning `None` on any DB error. It is
NOT a GitHub API/connector call (no OAuth, no network round-trip to GitHub) — it's the exact same
function the execute path already falls back to when no repo is named (line ~10532-10536), so this
is genuinely "the same resolver the execute path uses," reached without adding the kind of I/O
(GitHub connector) the gate's own docstring says drafting must not require.

**Order**: an already-known slash-form repo (`_gate_repo`, already extracted above, zero cost)
wins first; the default-repo DB read only runs when that's empty, and only strips when it returns
a value — a bare phrase that doesn't match the resolved target (no default configured, or default
names something else) is left untouched rather than guessed at, per `strip_repo_phrase_for`'s own
"never guess" discipline.

**No new regex**: reuses `strip_repo_phrase_for` verbatim (imported locally, matching the existing
local-import style at the file-time call site) — `TestExtractionPatternRatchet`'s pre-classifier
count (11) is untouched; confirmed via the architecture-enforcement run below.
