## Task

`ConversationContext.pending_list_remainder` (#1762) is in-process only. After a
restart/eviction, "show me the rest" finds nothing — ABSENT, not stale — and the
consume seam silently falls through instead of giving the GatherOutcome §5b-i
honest "that list has moved" turn.

Lead ruling: option 1, the cheap tombstone. Persist ONLY
`(kind, shown, held_total, source_total_display, armed_at)` — never the item
lines — into the #953 Layer-4 hydration slice alongside `last_offer`, so that
after a restart the remainder is *stale* (handled by the existing `render_moved`
path).

- Wiring: `services/intent/intent_service.py` `process_intent()` — hydrates once

  `self.conversation_manager.load_context_state(...)` then

  `context_state_for_db = conv_ctx.to_persistable_state()` (line ~869), handed to
  `_save_conversation_turn(..., context_state=context_state_for_db)`.

**The `_arm_list_remainder` / `_check_pending_list_remainder` seam**
(`services/intent/intent_service.py`, ~3463 / ~3633): arm writes
`ctx.pending_list_remainder = remainder` (in-memory only — the DB write is the
existing turn-end persist above, so nothing new was needed to make the arm
"write-through"). Consume: `remainder = ctx.pending_list_remainder`; if `None`,
returns `None` (falls through silently — the pre-#1784 defect for a *lost*
remainder, correct behavior for a *never-armed* one). If present, runs
`evaluate_acceptance(...)`; on ACCEPT it clears the store then branches
`if remainder.is_stale() or not remainder.lines: render_moved(...) else
render_cash(...)`.

**Key finding**: the `not remainder.lines` half of that guard already exists
and is unconditional. A hydrated tombstone (`lines=()`) therefore *structurally
cannot* reach `render_cash` — no new branch was needed at the consume seam at
all. The whole fix is making a tombstone actually arrive there via hydration.
