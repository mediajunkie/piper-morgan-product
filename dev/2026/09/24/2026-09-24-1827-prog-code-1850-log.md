## Task

Build a call-site-independent validator that `ConnectorBindingRepository.upsert` delegates to: for a managed connector key (`github`/`calendar`/`notion`/`slack`), a non-scheme-prefixed literal (droplet/Fly hostname, IP, bare path) is REJECTED naming the key it should have been; a scheme-prefixed BYOC URL and the logical key itself still write unchanged.

## ADR line that decided reject-vs-normalize

**It doesn't decide** — I read Amendment A (`docs/internal/architecture/adrs/adr-070-mcp-consumer-connector-architecture.md`, lines 271–287) in full. A1 says a managed binding "stores a logical connector key, not a URL" and describes what the row *should* hold; A3 defines the BYOC shape-discrimination (scheme-prefixed = literal override, bare token = key); A5's "Optional lint" line only proposes detecting a scheme-prefixed ref on a managed binding, not what to do with a non-scheme *literal*. None of these decide write-time reject-vs-normalize behavior. Per the dispatch instructions, defaulted to **reject** — documented the reasoning in `binding_write_guard.py`'s module docstring: a silent rewrite of caller intent is the same "value pinned without visibility into what changed it" shape Amendment A's own root-cause paragraph names as the problem, one layer earlier.

## Implementation

- **`services/connectors/server_ref_resolver.py`** — extracted the A3 shape-check into an exported `is_byoc_literal(value)` (same `("http://", "https://")` tuple `resolve_server_ref` already used), and had `resolve_server_ref` call it. Behavior-preserving refactor (single BYOC-shape authority, A2 discipline applied to the *shape check* too, not just resolution) — existing resolver tests unchanged and still pass.
- **`services/connectors/binding_write_guard.py`** (new) — `MANAGED_CONNECTOR_KEYS` sourced from `server_ref_resolver._KEY_TO_ENV` (never hand-listed); `ManagedConnectorRefRejected(ValueError)` names the connector and the offending value, tells the caller what to pass instead; `validate_mcp_server_ref(connector, mcp_server_ref)` no-ops for non-managed connectors, empty/None refs, BYOC literals, and the exact logical key — raises otherwise.
- **`services/connectors/binding_repository.py`** — `upsert()` calls `validate_mcp_server_ref(connector, mcp_server_ref)` **before** `self.get()`/`self.session.add()` (not just before the field assignment), so a rejected write neither creates a half-written new row nor touches an existing one — verified by dedicated tests.
