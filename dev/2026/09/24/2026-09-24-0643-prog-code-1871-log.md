## Decision: smallest change, one send path

Gave `SlackDomainService` a real `post_message` that delegates to `SlackIntegrationRouter.send_message` (lazily built + cached on the domain-service instance, mirroring the router's own per-user `SlackClient` laziness). Rejected the alternative (skill holds a `SlackIntegrationRouter` directly) because it would touch more call sites for no benefit — the domain-service seam is exactly the abstraction the skill already calls through, and this keeps `services/domain/*` as the one mediation layer between application code and Slack integration, consistent with the class's own docstring ("Mediates all Slack operations for the domain layer following DDD principles").

No blocks/thread_ts reimplementation — `post_message` builds a `kwargs` dict only with what's given and passes straight through to the router → `SlackClient.send_message`, which already owns that logic (and the `#1227` markdown→mrkdwn normalization).

## Change

`services/domain/slack_domain_service.py`:
- Import `SlackIntegrationRouter`.
- `__init__`: add `self._integration_router: Optional[SlackIntegrationRouter] = None` (lazy, not built eagerly — no user to scope it to at construction time).
- `_get_integration_router()`: lazily builds `SlackIntegrationRouter(SlackConfigService())` once, caches it.
- `post_message(channel, message, user_id, blocks=None, thread_ts=None) -> Dict[str, Any]`:
  - Raises `ValueError` if `user_id` is falsy (#1466/#1481 — never send as the connector owner; a caller bug fails loudly rather than silently degrading).
  - Delegates to `router.send_message(channel, message, user_id=user_id, **kwargs)`.
  - Catches transport exceptions → `{"success": False, "error": str(e)}` (not `services/domain` — outside `check_silent_death.py`'s `CORE_PATHS` scope, but written honestly regardless: no swallow, real reason returned, logged).
  - Maps a failed `SlackResponse` → `{"success": False, "error": <response.error.message>}`.
  - Maps success → `{"success": True, "channel": data.get("channel", channel), "ts": data.get("ts")}` — `ts` is `None`, never fabricated, if the response didn't carry one.

`services/integrations/mcp/skills/standup_workflow_skill.py` (`_post_to_slack`):
- Threads `user_id=user_id` into the `post_message` call (previously **not passed at all** — a second latent bug beyond the missing method: even after adding `post_message`, the old call site would have sent unscoped).
- Added an explicit `if not result.get("success")` branch → returns `{"success": False, "message": result.get("error", ...)}` (previously the skill unconditionally returned `success: True` regardless of what `post_message` reported — a second bug: a real Slack failure would have been reported as a success up through `execute()`'s `posted_to.append("slack")`).

### Before (defect)
```python
result = await self.slack_service.post_message(
    channel=slack_workspace.get("default_channel", "#standups"),
    message=slack_formatted["text"],
    blocks=slack_formatted.get("blocks"),
    thread_ts=slack_formatted.get("thread_ts"),

```
(`post_message` did not exist on `SlackDomainService` → live `AttributeError`; even patched, no `user_id` was threaded and any failure was reported as success.)

### After
```python
result = await self.slack_service.post_message(
    channel=slack_workspace.get("default_channel", "#standups"),
    message=slack_formatted["text"],
    user_id=user_id,
    blocks=slack_formatted.get("blocks"),
    thread_ts=slack_formatted.get("thread_ts"),
)
if not result.get("success"):
    return {"success": False, "message": result.get("error", "Slack post failed")}
return {"success": True, "channel": result.get("channel"), "timestamp": result.get("ts"), "message": "Posted to Slack successfully"}
```
