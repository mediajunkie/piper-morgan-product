### ⚠️ Why NO new `ListRemainder` arming site — the load-bearing finding

The Lead's brief expected this cohort to compose through `compose_capped_list` and arm a
remainder. **It should not, and the census is why:**

1. **The Lead's two named targets are already done.** `conversational_floor.py:~848` is the
   DUE REMINDERS block — fixed as class-(a) site a12 in `e8f6128cf`. And
   `intent_service.py:6647` was **never a render cap**: at the issue's filing commit
   (`4469c94ee`) that line sat inside the comment-on-issue repo-clarification branch. It is
   one of the two stale line numbers the 09-13 census already flagged. Every
   `canonical_handlers.py` line the issue cites (:886 :917 :938 :1265 :2070 :2174
   :2496/:2562/:2569 :2797) is likewise class-(a)-fixed.
2. **Every remaining site sits over a bounded or already-gather-capped set.** PIPER.md
   projects/priorities are hand-authored (the ratified class-(a) treatment is render-whole,
   shipped at six sibling sites and pinned by `TestPiperMdProjectRendersCarryFullSet` /
   `TestPiperMdPriorityRendersCarryFullSet`). `high_priority_issues` is held at 5.
   **PPM's threshold-3 rule reaches the identical outcome independently** — a hidden tail of
   ≤3 is ceremony, render them all — so `compose_capped_list` at these sites would emit
   *no offer and no remainder* anyway.
3. **Composing there would have been strictly worse.** These are pure `-> str` formatters
   with no `session_id`. If #1776 later lifts a gather cap, `compose_capped_list` would start
   emitting `"That's 3 of 20 — say the word…"` with **nothing armed behind it** — a promise
   the system cannot cash, i.e. the §5b defect newly manufactured by the fix for it.

So the store/seam question has an honest answer: **no new store key, no new seam.** The
existing store (`ConversationContext.pending_list_remainder`, written by
`IntentService._arm_list_remainder`, consumed by `_check_pending_list_remainder` →
`render_cash` / `render_moved`) is untouched and remains the GitHub six's alone. Re-read
end-to-end this session to confirm it is reachable from any writer of that field — it is —
so when a portfolio site *does* need arming it can reuse the seam verbatim without a new
mechanism. It does not need it today.
