## Task

Lead's trace: in `web/api/routes/intent.py` `process_intent`, the #731 auto-create block creates the
`ConversationDB` row, then the #1807 `UserLLMKeyRequiredError` gate returns BEFORE `intent_service` runs
(where turn persistence lives via `conv_ctx.add_turn` / `ConversationRepository.save_turn`). So the
refused exchange is never saved. Build: persist both turns (user message + gate reply) via the SAME
repository call the normal path uses, best-effort, never let persistence failure change the response.
Also set conversation title if reachable the same way the normal first-turn path does.

Own: `web/api/routes/intent.py` and my tests. `services/database/repositories.py` only if a helper
genuinely needs to live there.

  matching the #731 block immediately above (same route-boundary/possibly-different-event-loop
  rationale, #442).

## Fix

`web/api/routes/intent.py`:
- Added `_persist_keyless_refusal_turn(session_id, user_id, user_message, assistant_message)` — best
  effort, calls `ConversationRepository.get_next_turn_number` then `.save_turn` directly inside
  `AsyncSessionFactory.session_scope_fresh()`, builds one `domain.ConversationTurn` carrying both the
  user's message and Piper's refusal (matches every other turn's shape — one row, not two). Wrapped
  in try/except mirroring the #731 block's own discipline; failure is logged as a warning and never
  propagates or changes the response.
- Wired into the `except UserLLMKeyRequiredError:` branch (the #1807 gate, ~line 578): builds the
  refusal response first, then calls the persist helper (guarded by the SAME condition the #731
  auto-create block uses: `user_id and session_id and session_id != "default_session"`), then
  returns the (unmodified) refusal response.
- Did NOT touch `AnonymousLLMKeyRequiredError` (#1320) or the expired-session (#1520) branches —
  confirmed with Lead's framing: no user_id on those paths, no conversation row to attach to.
