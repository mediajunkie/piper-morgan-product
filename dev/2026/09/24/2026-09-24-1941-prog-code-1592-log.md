### Fix

The ERROR only ever fires from one place: `GoogleCalendarMCPAdapter.authenticate()` in
`services/mcp/consumer/google_calendar_adapter.py` (the missing-`credentials.json` branch,
originally line 368-372). Every construction path above — scoped or not — funnels through this
one method, so the fix belongs there rather than at any individual call site (and that's exactly
why it needs zero changes to the excluded files: the temporal handler, the one `intent_service.py`
line, and the feed builders all inherit the fix automatically via whatever `user_id` they actually
had at runtime).

Added a `_is_user_scoped` property (`bool(self._user_id) and self._user_id != "system"` — "system"
is the constructor's existing sentinel for "no user_id given"). In the missing-`credentials.json`
branch: scoped → unchanged `logger.error(...)`; unscoped → `logger.info(...)` with an honest
message ("no user scope; the per-user keychain path is the live one on hosted deploys"). Also used
the new property (pure refactor, no behavior change) in `_authenticate_from_keychain`'s existing
scoping check, which was already correctly at INFO.
