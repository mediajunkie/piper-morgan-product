```
Returns True ONLY for intents that need side effects, database writes,
```

🔴 **`CANONICAL` means "the LLM cannot do this alone." It does NOT mean "this costs no LLM call."**
For a *spend* gate those are near-opposite: EXECUTION and PORTFOLIO are canonical **because they
write to the database and create issues.** **My ruling, implemented literally, would have opened a
keyless path to issue creation** — materially worse than the refusal it was softening.

**Where it bit is the part worth keeping.** Not in a value I misread — **in a name I trusted.** I
reasoned from the word *canonical* and from `ACTION_REGISTRY`'s own comment `fast-path/deterministic`,
which is true of *some* canonical pairs and false of most. That is my own week-old rule one level up:
*a grep line-hit is not a read* → **a name is not a definition, and a registry's comment describing
an authority is not the authority.** Fifth honest-empty instance in eight days.

**Corrected ruling**: the property doesn't exist and must be **created** — a distinct
"this turn spends nothing" predicate **defaulting to `False`**, so a handler is not exempt unless
deliberately marked *and* proven. The default *is* the safety property. What survives: property-not-
list, and the ordering cure (pre-classify first; `PreClassifier` is regex, zero LLM calls — verified,
and still verified).

⭐ **Lead's ratchet becomes the definition, not a regression test.** Their instrument — drive each
pair keyless with `complete` rigged to explode — is right, but the expected result is no longer
