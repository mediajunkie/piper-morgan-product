### 06:56 AM — PM direct report: sitewide dark-mode contrast bug, root-caused and fixed

PM sent a screenshot (direct conversation, not mail) of the freshly-published Ship
#059 post in dark mode — nav correctly dark, but content area rendering washed-out
light-gray text on a light-gray background, nearly illegible. Message was addressed
to "Docs" — flagged the mix-up plainly and picked up the substance anyway since it's
squarely Web's lane.

**Investigated before fixing, not guessed**: confirmed dark mode was genuinely
active (checked `ThemeToggle.tsx`'s icon logic — sun icon shown means current theme
is dark). Traced `ShipPostContent.tsx`'s structure: outer wrapper uses
`bg-gray-50 dark:bg-dark-bg`, while its `.prose dark:prose-invert` content correctly
inverts text to light-on-dark coloring — meaning the mismatch (light text on a
still-light background) pointed at the background class specifically not applying.

**Root cause, confirmed via the compiled Tailwind config, not assumed**:
`tailwind.config.ts` defines the dark-background color token as `dark-background`
(`#0F172A`) — but `dark:bg-dark-bg` (referencing a token named `dark-bg`, which
doesn't exist) was used at every call site instead. Tailwind's JIT compiler silently
drops classes referencing undefined tokens rather than erroring, so the class
compiled to nothing, sitewide, for as long as it's existed — `git log -S` on the
real token name shows it's been `dark-background` since the initial commit
(2025-08-08), so this was never a regression, just always-broken.

**Scope was much larger than the one reported page**: `grep` found **8 files, 10
occurrences** — every regular blog post (`BlogPostContent.tsx`), every Ship post
(`ShipPostContent.tsx`), the Shipping News landing page, and 5 admin pages (login,
calendar, compose, publish-queue, AdminGate). Fixed all 10 occurrences to the real,
already-existing token name rather than add a duplicate alias — investigated the
config before extending it. Verified count matched exactly (10 before, 10 after,
0 remaining broken references) before committing.

Production build clean. Confirmed the fix actually compiles real CSS
(`.dark\:bg-dark-background{background-color:#0f172a}`, matching the site's
established dark-background color used elsewhere via CSS custom properties) rather
than trust a clean build alone. Committed (website `70791c3`) with full root-cause
evidence in the commit message, pushed, deploy verified `success` via GitHub
commit-status API poll. Reported to PM in chat — fix live, scope larger than the
one reported page (10 occurrences, 8 files, sitewide).
