## Root cause and the two fixes — both implemented and independently tested this morning

Pard named two defects, both required before any re-arm:

**1. No re-entry guard.** Fixed in `.claude/hooks/post-commit.sh`: an exported environment variable
(`PIPER_IN_POST_COMMIT_HOOK`), checked first, before any other work. A recursive child inherits its
parent's exported environment — this is airtight against the actual failure mode (process-tree
depth), not a heuristic. **Tested directly**: `env PIPER_IN_POST_COMMIT_HOOK=1 bash
.claude/hooks/post-commit.sh` exits silently at 0, confirmed it never reaches the heartbeat call.

**2. A hook that pushes.** Fixed in `scripts/duty-cycle-heartbeat.sh`: a new `--no-push` flag
(required a small arg-parsing generalization to support multiple flags cleanly) that commits the
marker locally and stops — no fetch/merge/push from a hook context. Delivery now rides the agent's
own next real push, per Pard's own framing ("let the fire's own delivery carry it"). The hook now
calls `duty-cycle-heartbeat.sh cio WORK --if-quiet --no-push`.

**Added a third, independent guard** or belt-and-suspenders as Pard's report explicitly invited
("either alone stops the loop; both is cheap"): `duty-cycle-heartbeat.sh` now checks whether `HEAD`
is already one of its own marker commits (message prefix `hb(` / `hb-last-invoked(`) and refuses to
react if so — catches the recursion shape even if something other than this hook's own subprocess
tree ever calls the script against a marker commit. **Tested directly, end to end, without touching
the disarmed hook**: ran `duty-cycle-heartbeat.sh cio WORK --if-quiet --no-push` (committed a real
marker locally, confirmed via `git log -1`), then ran it again immediately — HEAD was now that
