## Design decision — one representative-category test per file, not 13

Batch 2 established two precedents: `test_multiuser_contracts.py` (13 per-category tests, the reference
shape) and `test_error_contracts.py` (1 test, because every original test in that file used the SAME
category-invariant probe — `message = ""` — so a single authenticated test fully covers the property).

For my five files, the property under test — does `process_intent`'s outer turn-recording seam
(`get_or_create_context` + `conv_ctx.add_turn`, `services/intent/intent_service.py` ~L765-819) thread
`user_id` correctly — is itself category-agnostic and already exhaustively proven across all 13 categories
in batch 1's `TestMultiUserContractsAuthenticated`. Re-proving that same mechanism 13 more times per file
(65 more tests total) would not add coverage of a NEW property, only re-run the same seam under different
messages. I added ONE authenticated test per file, using TEMPORAL (a Stage-1/deterministic-pre-classifier
category) as the representative probe, and documented this rationale in each file's module docstring so
the choice is legible to the next reviewer/batch. This keeps the batch efficient while still flipping all
5 files from BLIND to non-blind and proving each file's OWN distinguishing property (accuracy / no-bypass /
performance / CLI-mocked-path / DIRECT-llm-tier-path) also holds per-user.
