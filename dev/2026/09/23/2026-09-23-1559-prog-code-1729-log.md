## Summary

Found and fixed the real cause: `services/intent_service/document_handlers.py`,
`handle_summarize_document`'s `format == "bullet"` branch (the DEFAULT format,
used both by the REST `/summarize` route and the chat `summarize_document`
rail — confirmed via `web/api/routes/documents.py:233` and
`services/intent_service/workflow_entries.py:1015`).

### Mechanism

`analysis["summary"]` is always `DocumentSummary.to_markdown()`'s output
(`services/domain/models.py:1108`), which unconditionally starts with
`"# {title}\n\n"`. The bullet-format guard was:

```python
if not summary_text.startswith("•") and not summary_text.startswith("-"):
    sentences = [s.strip() for s in summary_text.split(".") if s.strip()]
    summary_text = "\n".join([f"• {sent}" for sent in sentences[:5]])
```

Since a markdown summary never starts with `•`/`-` (it starts with `#`), the
guard never matched — EVERY summary, including a fully-formed
`"## Key Findings\n\n- item\n  - subitem\n"`, fell through to the
period-split "bulletizer." That step splits the whole markdown blob on `.`
with zero regard for block/list boundaries, so a nested list item's own
newline+indent survives as literal text mid-chunk, and an errant `"• "` gets
glued to the front of each chunk. That's the exact `• -` run-on PM saw.

Separately, even the genuine plain-prose fallback path (no-LLM/failure
summaries like "PDF with N pages...") used the Unicode `•` glyph, which
`marked.parse` (the live renderer, `web/assets/bot-message-renderer.js`,
wired via `templates/layouts/app_shell.html:80`) does not recognize as
CommonMark list syntax — those lines rendered as plain text joined by soft
breaks (single `\n` inside a paragraph collapses to a space per CommonMark,
no `breaks:true` set), i.e. the same collapse-to-one-paragraph failure mode,
independently. This is the identical mechanism #1615 already diagnosed and
fixed at the first-contact demo site (`services/intent_service/first_contact.py:246-251`).

### Fix

1. Wired in `has_markdown_formatting()` (`services/utils/markdown_formatter.py`
   — pre-existing, well-written, but **dead code with zero callers** before
   this fix — a "75% complete" pattern, completed rather than duplicated per
   CLAUDE.md). It detects markdown structure (headers/bullets/bold/etc.)
   ANYWHERE in the text, not just a leading glyph, so a real
   `to_markdown()` summary is correctly recognized and left untouched.
2. Changed the plain-prose fallback's bullet glyph from `•` to `-` (real
   CommonMark list marker) so genuinely unstructured summaries also render
   as a real list instead of one collapsed paragraph.

File: `services/intent_service/document_handlers.py` (import + ~25 lines in
`handle_summarize_document`).
