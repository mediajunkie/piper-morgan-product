## Census script changes (scripts/census_principal_blind_tests.py)

Three additions, each evidenced by exactly one file above (no speculative extension):

1. **Archive exclusion** — `tests/archive/` is skipped entirely during the `TESTS.rglob("*.py")`
   walk (mirrors `pytest.ini`/`pyproject.toml`/`tests/conftest.py`'s independent exclusions).
2. **Positional user_id** — `get_or_create_context`/`clear_context` (both
   `(session_id, user_id=None)`) now also check the 2nd positional argument. Carefully
   distinguishes a bare positional value from a `user_id=None` KWARG landing at that same
   position (caught a real bug during authoring — see below).
3. **`current_user=` for `process_intent`** — the HTTP route wrapper shares the name with
   `IntentService.process_intent` but carries identity via `current_user.sub`, not `user_id=`.
   Scoped ONLY to `process_intent` calls (verified inert for the other four KEYED_CALL_NAMES).
4. **By-design marker** — a standalone `# principal-blind-by-design: <reason>` comment anywhere
   in a file moves it from BLIND to a new BY-DESIGN bucket. Still scanned and keyed (denominator
   stays honest); listed separately with its reason. `--count` (the ratchet-read output) still
   means **true BLIND only** — by-design files never inflate it.

Docstring updated to keep the "known blind spots" list honest: removed the now-fixed spots,
added the three new recognized shapes with their evidence file, and kept the still-open ones
(positional user_id on `process_intent`/`should_offer`/`record_offer` — not extended

**Bug caught and fixed during authoring**: my first positional-detection pass misread
`get_or_create_context(session_id, user_id=None)` as REAL, because the "is this actually some
other kwarg at this position" exclusion special-cased names starting with `user_id` to always
pass through, then compared the literal string `"user_id=None"` against `"None"` (never equal).
Fixed by extracting the kwarg's name/value pair when the positional slot holds a `name=value`
form, and only trusting it when `name == "user_id"`, comparing against the VALUE not the whole
`name=value` text. Caught by directly testing `_has_real_user_id` against the exact
`get_or_create_context(session_id, user_id=None)` call text from file #10 before touching any
test file — regression-pinned in the new census test (`test_kwarg_user_id_none_in_second_
position_is_still_blind`).
