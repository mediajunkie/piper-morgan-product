## Fix (services/config/llm_config_service.py)

- Added `_safe_response_body(response, limit=500)`: best-effort, truncated provider
  response-body text (never raises). `except Exception: return ""` annotated
  `# silent-ok:` (services/config is in the silent-death ratchet's CORE_PATHS scope;
  unannotated would have pushed the ratchet from 192 to 193 and failed the smoke sweep
  — caught by `scripts/run-sweep.sh smoke`, fixed, ratchet count confirmed back at 192).
- Added `humanize_validation_result(result: ValidationResult) -> str`: builds
  `f"{error_code}: {error_message}"` and runs it through
  `services.ui_messages.user_friendly_errors.make_error_user_friendly` (the SAME
  translator/strings the runtime chat path uses) — only substitutes when the translator
  actually recognizes it as an `llm_key` cause; otherwise passes the raw `error_message`
  through unchanged (never downgrades an unrecognized cause to a vaguer generic line).
- `_validate_openai`: now separates 401/403 (`AUTH_ERROR`) from everything else
  (`VALIDATION_ERROR`) — fixes the pre-existing OpenAI-only mislabeling bug above — and
  both branches now include `_safe_response_body(response)` in `error_message`.
- `_validate_anthropic`: both branches (already correctly split) now also include the
  response body.
- Added `validate_api_key_detailed(provider, api_key) -> ValidationResult` (the full
  result). `validate_api_key()` is now a thin bool wrapper delegating to it — every
  existing bool-consuming caller is unaffected (verified: `main.py`, `validate_user_key`,
  `rotate_user_key`, all pass through unchanged).

    Documented in the docstring.

## Fix (web/api/routes/api_keys.py)

- `store_api_key`: added `assert user_key is not None` (route never passes `store=`, so
  it's always the store=True/non-None path — also fixed 3 mypy union-attr false
  positives). When `request.validate` was actually attempted AND validation failed,
  `StoreKeyResponse.message` carries `user_key.validation_message` (falls back to a
  generic "saved, but could not be validated" only if that's somehow unset). Explicitly
  does NOT substitute when `request.validate=False` — skipping validation isn't a
  "failure," and saying so would be dishonest in the other direction.

## Fix (templates/settings_llm_keys.html)
