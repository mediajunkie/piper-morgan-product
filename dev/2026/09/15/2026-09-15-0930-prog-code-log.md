### 09:35 — Gap 1 reproduced RED, then fixed

**Reproduction (new test file, run before any source change):**

```
FF.F.
AssertionError: the routed turn failed instead of falling back:
  RuntimeError('All configured LLM providers failed. Details: openai: openai upstream
  returned 503 service_unavailable') — the fallback loop skipped Anthropic despite a
  usable per-request key (#1815 Gap 1)
3 failed, 2 passed
```

The world that produces it: operator's OpenAI key configured server-side, tester BYOCs their
own Anthropic key, `PIPER_DEFAULT_PROVIDER` at its shipped default `"openai"`. Primary resolves
to openai, openai has a bad minute, the fallback loop reaches Anthropic — and
`_is_provider_configured(ANTHROPIC)` reads the SERVER's `anthropic_client` (None post-#1810),
`continue`s past the only provider that could have served the request, and the floor hands the
user the generic transient copy. No Anthropic client was ever constructed.

**Fix** — `services/llm/clients.py::_is_provider_configured`. Reuses #1814's shape rather than
inventing a parallel one: read the SAME ContextVar the consumer reads.

```python
from services.llm.request_key import REQUEST_KEY_PROVIDER, get_request_api_key

if provider.value == REQUEST_KEY_PROVIDER and get_request_api_key():
    return True
```

Two constraints held deliberately:
1. **Anthropic only, named via `REQUEST_KEY_PROVIDER`** — `_openai_complete`/`_gemini_complete`
   have no per-request path at all. Reporting them available off an Anthropic request key would
   route the loop into a provider guaranteed to raise: a silent skip traded for a guaranteed
   failure, which is not a fix. (This is the constraint #1815's body calls out by name.)
2. **Nothing constructed, nothing stored** — so #1814's singleton-contamination guard is
   untouched. `_init_clients` stays request-BLIND (`include_request_key=False`). The Lead's
   stop-and-report condition does NOT trigger: `_is_provider_configured` is a pure read with no
   assignment to `self`, and the key still reaches Anthropic only via
   `anthropic_client_for_request`, which builds a fresh client per request.
