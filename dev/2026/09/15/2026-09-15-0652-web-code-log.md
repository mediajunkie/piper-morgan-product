### 10:2x AM — P0: text typed BACKWARDS in the compose editor (my regression, fixed)

PM reported typing "odd" produced "ddo" in the blog-editing interface. **My own
regression from yesterday's `bb579b5`** (the Source/Split/Preview toggle) — one
day old, in PM's primary authoring tool.

**Mechanism**: the caret-restore `useLayoutEffect` declared deps
`[bodyView, body]` while *its own comment* said "must fire on remount, not on
every keystroke." Every keystroke changed `body` → effect re-ran → restored the
caret to the **pre-keystroke** position held in `caretRef` → the next character
landed in front of the last. The code and the comment directly contradicted each
other and I shipped it; the comment was the correct intent.

**Fix** (`45ab4a9`): guard on a `restoredViewRef` rather than the deps array.
`body` must stay in the deps (the preview scroll math reads it), so a
view-change check — not dep removal — is what enforces the intent.

**Verified how**: Playwright driving a real dev server against an **isolated temp
`PIPER_PRODUCT_ROOT`** (copy of the drafts tree — no real draft reachable by any
test action). Layer is **real browser keystrokes**, not compile or render.
4/4 pass. Then **reverted the guard and re-ran to prove the test can actually
detect the bug** — reproduced PM's exact symptom (`"odd"→"ddo"`,
`"hello"→"olleh"`, caret pinned at origin) — then restored (sha-verified) and
re-confirmed 4/4. Denominator: 4 cases — type-at-start, type-mid-document,
toggle caret round-trip (the `bb579b5` feature, confirmed still intact), and
typing after a toggle. `tsc` clean for this file (7 pre-existing strict-null
errors elsewhere, 0 here); production build clean.

`bb579b5..45ab4a9` is a direct parent-child pair, so the regression window is
exactly those two commits — no other work implicated. Deploy poll running.

**The lesson worth keeping**: yesterday I browser-verified the *feature* (caret
survives a toggle — which passes, and still passes) and never tested the
*ordinary* path the feature shares state with. A test of the new behavior is not
a test of the behavior it perturbs. m-43 layer-naming would not have caught this;
"what else touches this state" is the question that would have.

**Deploy**: `45ab4a9` Vercel state=**success**. Fix is live.
