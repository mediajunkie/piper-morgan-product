### Fire 4 — Blast radius of fixing type resolution

`typing.get_type_hints()` fails on **24 of 55** domain dataclasses:
`TypeError: type 'List' is not subscriptable`.

Cause: `services/domain/models.py:1482` defines `@dataclass class List:` ("Universal List model"),
which **shadows the `typing.List` imported at line 16**. Only `List`, `Set`, `Type`, `Union`
resolve differently; no field anywhere is annotated with the bare domain `List` type (even
`class List` itself writes `tags: List[str]` meaning `typing.List`), so restoring the `typing`
names in the resolution namespace is semantically what every annotation intends.
→ **Discovered work, filed separately (#1789).** Harmless at runtime (annotations never
evaluated under PEP 563) but breaks all runtime type introspection on those 24 models.
