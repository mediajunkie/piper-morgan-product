## What was built

1. **New module**: `services/intent_service/scope_guard.py`
   - `SOURCE_FAMILIES` — the synonym table (5 families: todos, reminders, calendar,
     projects, github), each mapping to zero or more `SOURCE_FAILED_FLAGS` check_names.
     `calendar` maps to **zero** check_names deliberately — it is not a registered flag
     at all (the leak corpus's own finding), so it is always-unarmed by construction,
     no special-casing needed.
   - `_FAILURE_CLAIM_RE` — the failure-verb vocabulary (don't have, couldn't check,
     wasn't able to, no access to, not available, unchecked, failed to ..., etc.),
     built from the issue's own listed verbs plus the corpus.
   - `_sentence_verdict` — the classifier: drop a sentence iff it names an unarmed
     family AND carries a failure-claim, UNLESS it also names an armed family (kept,
     documented decision: the true claim about the armed source would otherwise be
     lost to filter the false half).
   - `apply_scope_guard(text, armed_check_names, ...)` — paragraph/sentence split,
     drop, reassemble; zero regex work when `armed_check_names` is empty; falls back
     to `build_fallback_sentence` when dropping empties the reply or leaves a
     word-count-<3 fragment; logs `floor_scope_guard_dropped` (count + unarmed source
     names, never reply text).
   - `build_fallback_sentence(armed_check_names)` → `"I couldn't check {names} this
     turn."` (marked `# CXO copy pass owed`).

2. **Wired into `ConversationalFloor.respond()`** (`conversational_floor.py`):
   runs right after `strip_placeholder_slots`, before the `conversational_floor_hit`
   log line, computing `armed_check_names` from the same `SOURCE_FAILED_FLAGS` registry
   the prompt itself used. `FloorResponse` gained `scope_guard_dropped: int = 0`
   (also folded into `to_log_dict`).

3. **Tests**: `tests/unit/services/intent_service/test_scope_guard_1772.py` (40 tests,
   all pure-function or stubbed-LLM `respond()` tests — no live LLM calls).
