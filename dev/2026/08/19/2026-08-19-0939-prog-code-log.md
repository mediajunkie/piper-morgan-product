## Design decisions (recorded before build)

1. **Armed rows live in a SEPARATE fixture file**
   (`tests/fixtures/inversion_corpus_phase2_armed.yaml`), not appended to
   the phase0 YAML. Three reasons: (a) phase0 corpus header says GENERATED —
   hand rows belong in the builder, but the builder dedupes by phrase key,
   which would merge each armed row with its same-text control twin;
   (b) adding asserted rows to phase0 categories silently shifts every
   denominator that scripts/inversion_phase1_shadow_score.py compares
   against its frozen PHASE0_BASELINE dict — corrupting future rerun
   comparability; (c) "preserve every existing row untouched" is satisfied
   byte-for-byte.
2. **Expected vocabulary gains `route:NONE` / `route:CLARIFY`** for rows
   whose correct routing decision is a sentinel, per the snapshot contract's
   serialized RULE (answers to the open question belong to the flow's
   handler, which is not a catalog operation → NONE).
3. **Fixture keys are EXACTLY SessionSnapshot field names**; the runner
   constructs the real dataclass via SessionSnapshot(**fixture) so an
   unknown key fails loudly, and serializes via serialize_for_prompt —
   never a hand-rolled block.
4. **Conditions**: fixture rows run twice (with state_block / without);
   control twins and phase0 rows run once (their with/without prompts are
   byte-identical by construction — running twice would measure only
   stochasticity and muddy the comparison; stated in the report).
5. **No tuning on outcome** — whatever the router does on the armed rows is
   the reported result (task item 4).
