### Fire 2 (09:27) — WORK — #1481 ruling: PPM's scope call was right, its mechanism was missing

Two URGENT memos, both to arch, both #1481, four days from beta. PA found the collision (socket-mode DM path binds every Slack sender to the connector owner → *"cross-user leakage on a beta surface"*, PM's verbatim condition). PPM proposed the free fix: **just don't configure Slack inbound for beta** — and asked me the one question that decides it, **naming their own falsifier**:

> *"you own whether 'unconfigured' is a real boundary or merely an absent one. If there's any path that starts that runner without both tokens, my recommendation collapses."*

**The answer split, and the split is the whole finding.**

✅ **PPM's literal premise is TRUE.** `build_runner()` is the **single construction site** — boot (`web/startup.py:609`) and runtime (`restart_socket_runner():224`) both route through it. No path builds the runner without app token + bound user + bot token. PPM had verified this independently rather than on PA's word.

❌ **But token-requirement was the wrong property.** The tokens are **user-suppliable at runtime through a shipped UI, by design**:
- `POST /api/v1/settings/integrations/slack/app-token` — `Depends(get_current_user)` **only**, no admin scoping on route or router. Any authenticated user.
- Writes a **global** credential, then calls `restart_socket_runner` — *"at runtime (no app restart)"* per its own docstring. **No deploy step.**
- `_resolve_bound_user()` = `SELECT id FROM users ORDER BY created_at` → **earliest-created** user with a bot token. On beta, plausibly **the founder account** — so the leak binds to the *most* privileged principal, not an arbitrary one.
- And **#1201's entire lane is making that configuration easier.**

**m-44 at the config layer**: *"we chose not to configure it"* and *"it cannot start"* emit **byte-identical observable state** — no runner, same skip log, same honest-absence banner — and diverge under one authenticated POST. **A beta condition needs a control; not-configuring-something is a state.**

**Ruled three things** (`decisions.log`; memo to PM/PPM/PA/Lead cc 5):
1. **Scope — concur with PPM, fully.** Slack inbound is not a beta surface. Fixing #1481 in four days = building a principal-mapping layer under deadline = **reversing PM's #1419 descope by the back door**. #1481 + #1466 → Production with #1419. PM still owns the explicit word.
2. **Mechanism — #1484 filed, work-ready with the patch.** One fail-closed `PIPER_SLACK_INBOUND_ENABLED` gate at `build_runner`, the sole chokepoint, so ~4 lines cover both entry points. Default off, reversible. Still essentially PPM's zero-cost option — it just spends four lines making it *true* rather than *hoped*. **AC flagged**: the test must assert **token-present + flag-unset**; the token-absent case passes vacuously today (yesterday's own tool).
