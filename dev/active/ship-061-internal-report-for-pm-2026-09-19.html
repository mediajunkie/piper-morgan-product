⚡ Vercel — do this now, it takes about two minutes

The problem is Deployment Storage at 100% of the 10 GB free tier — not traffic. "Congrats on your traffic" in Vercel's email is boilerplate; the metric named in it is storage.

🔴 And the fix is not deleting deployments one by one. It's a retention policy, which is also the answer to "what's recurring": every push creates a preview deployment, and without a retention period they accumulate forever. Deleting by hand clears the symptom and it refills.

Set the team default

  1. Open Team Settings → Security & Privacy
  2. Find Deployment Retention Policy
  3. Set periods for Canceled, Errored, Pre-Production, Production
  4. ⚠️ CLEAR the "Apply this policy to all existing projects" checkbox unless you actually intend to overwrite every existing project's policy — Vercel's own docs flag this, and it is the irreversible-looking step on the page
  5. Save

What to set each period from (Vercel's framing, which is a sensible way to decide):

statekeep long enough forlikely the big one for us
Pre-Productioncode review, QA, external approvals, regression investigation✅ yes — this is where per-push previews pile up
Productionincident recovery, rollback, release auditskeep generous
Canceled / Erroredbuild debugging✅ safe to make short

Per-project instead of team-wide: open the project → Settings → Security → Deployment Retention Policy. Affects only that project.

Instructions: vercel.com/docs/deployment-storage/optimize. ⚠️ Retention changes affect stored history over time, not instantly — Vercel's Usage page refreshes on its own schedule, so don't read an unchanged number five minutes later as failure. Web stays access-blocked until they have a token, so this one is yours or Pard's.
