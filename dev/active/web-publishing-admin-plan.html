Mechanical, agent-callable, stable
Non-interactive throughout. Stable CLI flags. JSON exit reports. Both human shells and pure-agent invocations route through this layer.

Queue browsing → metadata inspect/edit → mark-ready → open-in-$EDITOR handoff → dry-run preview → real publish via publish-post.js → diff → commit/push prompt → edit-pass mode for post-publish-edit awareness.

Sizing (post-discussion)

~7 hours total (revised down from ~7–8hr). Split: walking-skeleton (queue display narrow + pick + invoke + diff + commit prompt default-N) ~3hr → enrichment (gray-matter metadata edit + P]ublish/R]eady branching + open-in-$EDITOR + edit-pass + Docs-notify memo) ~4hr.

Resolved design decisions (2026-05-17 evening)

#QuestionDecision
1Commit + push or hand back?Auto with confirm, default-N. Auto-generated message with [e] edit option.
2Notify Docs after publish?Auto-drop short memo to mailboxes/docs/inbox/, CC PM. Extend existing channel.
3Mark-ready as separate state?Collapsed for v1, with P]ublish now / R]eady for later branching prompt. R-path supports goal-state scheduled-publish workflow incrementally.
4Edit-pass drift detection?No detection in v1. Always offer on published entries; empty git diff signals no changes.
5Queue picker scope?Narrow: queued/drafted/ready sorted by pubDate. Wider "recently published" variant filed as future.
6--non-interactive mode?Skip entirely. Agents use engine layer directly. CLI B is purely human-interactive.

Full discussion record in the design sketch's "Resolved design decisions" section.

Open issues #

Blog-index syndication-dup filter shipped 5/17

medium-posts.json contained both blog-first canonical AND RSS-syndicated duplicate as separate cards on /blog/. Root cause: fetch-blog-posts.js's slug-match heuristic missed the case where Medium auto-derives a longer title-slug.

Fix: loadSyndicatedHashIds() in fetch reads calendar's blogPath+mediumURL correspondence. One-shot cleanup script cleanup-medium-posts-duplicates.js (audit-before-delete + quarantine to .json.quarantine.json). Applied: 1 entry (archaeological-debugging) removed. Website 5c2bad168.

Cross-cutting principles #

These shape every decision; honor them in future work.

  • Human-first, agent-aware interfaces — PM is the primary user; architect every surface so agents can also consume it. (feedback_human_first_agent_aware_interfaces.md)
  • Conservative deletion · don't lose unique info · agent-ready from start — quarantine > rm; audit before delete; build agent-readable surfaces from day one. (feedback_conservative_deletion_agent_ready_unique_info.md)
  • Unblocked work + batched questions — do scoped work to completion or surface why you're not; batch questions; routine website commits don't need per-item approval. (feedback_unblocked_work_batched_questions.md)
  • Bias to immediate action — schedules are theoretical; act on next ready thing whenever possible; offer-first for half-day+ pieces. (feedback_bias_to_immediate_action.md)
  • Deferral requires PM approval — never unilaterally defer; surface with reason + recommended trigger. (feedback_deferral_requires_pm_approval.md)
  • Extend existing mechanisms until they overload — reuse established channels (inbox memos, calendar entries, git history) before introducing new surfaces. PM-stated 2026-05-17 evening during CLI B discussion. (feedback_extend_existing_mechanisms_until_overload.md)
