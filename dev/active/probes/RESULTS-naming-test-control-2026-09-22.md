# BYOC tool-catalog naming test — independent-author control, second pass

**Author**: PA. **Run**: 2026-09-22, 19:13 PT. Follows
`dev/active/probes/RESULTS-naming-test-first-pass-2026-09-22.md`, which found situation-shaped
12/12 vs. object-shaped 10/12 but flagged a real confound (PA wrote both catalogs in one sitting,
and the situation-shaped descriptions naturally came out more disambiguating).

**Authorized to run without a separate spend ask**: PM's 2026-09-22 fleet directive ("do not
self-throttle or postpone work over usage right now... drain your queues normally") explicitly
lifted the exact caution the first pass's cost-narrowing cited. The "honest next step" the first
pass named (an independent-author control) was ready to run and no longer needed to wait for a
separate authorization.

## Method: what changed, what didn't

**Changed**: the object-shaped *descriptions* — a fresh, isolated agent with no knowledge of this
test, the situation-shaped alternatives, or that its output would be compared to anything wrote
one description per operation, told only to write a good API-reference description. Object
*names* are unchanged (`create_issue`, `close_issue`, etc.).

**Unchanged**: the situation-shaped catalog, all 12 utterances, the model (`claude-sonnet-5`), the
scoring method — a clean, controlled comparison against the first pass.

## Result

**Object-shaped: 11/12 (up from 10/12). Situation-shaped: 12/12 (unchanged).**

## What this actually shows — more precise than the first pass

**One of the two original failures was confirmed as the confound.** `delete_todo` — object-shaped
now succeeds. The independently-authored description ("...rather than being completed or converted
into a tracked issue") disambiguates exactly the way the situation-shaped version did, once someone
wrote it with real care. **This confirms the first pass's own diagnosis**: that failure was about
description quality, not naming scheme.

**The other failure persists even under a good independent description.** `list_projects` still
loses to `attention_query` for *"Remind me what I've got going on right now"* — with the
independent author's description in place (*"for orientation or navigation when the user needs to
see what projects exist rather than details of any single item within one"*), which is a
genuinely clear, well-written description. Two honest readings, and this pass can't fully
discriminate between them:

1. **A residual, narrow naming-scheme effect** — situation-framing still helps specifically for
   inherently ambiguous utterances, even when object-shaped descriptions are well-written.
2. **A genuinely hard test case, independent of either naming scheme** — *"what I've got going on"*
   plausibly means either "what needs my attention" or "what projects exist," and a human asked
   the same question might also need to clarify. The situation-shaped alternative
   (`show_me_what_im_working_on`) happens to disambiguate this specific phrasing well, but that
   could be luck of phrasing rather than a property of situation-shaping in general.

**Net, across both passes**: the apparent 2-point gap in the first pass was mostly (not entirely)
a same-author artifact. Controlling for it narrows the gap to 1 point out of 12, on one specific
hard case. This is a much weaker, more honest claim than "situation-shaped wins" — and a
meaningfully different one from "no effect either way."

## What this still doesn't answer

Still n=1 per cell, still Claude only, still 12 operations (not the full ~53). A different
utterance for the `list_projects`/`attention_query` ambiguity, or a GPT run, could go either way.
This is two consistent, small, honest data points — not a settled answer to PPM's PDR-006 question.

## Recommendation, if this line of work continues

The one remaining open case (`list_projects` vs. `attention_query`) is worth a targeted follow-up
— vary the utterance for just that pair (2-3 more phrasings) before drawing any conclusion about
whether it's a real naming effect or a hard-case artifact. That's a small, cheap, targeted
extension, not a full re-run — naming it, not executing it, since it's a genuinely separate
decision from "run the control" and this pass already answers what it set out to answer (confirm
or rule out the confound).

**Verified how**: all 24 API calls run live this fire (`claude-sonnet-5`, same harness as the
first pass), raw JSON saved (`probe_naming_test_control_results_2026-09-22.json`). The independent
object descriptions were generated by a separate agent dispatch this fire, verbatim, not edited
before use — the exact isolation the control requires.
