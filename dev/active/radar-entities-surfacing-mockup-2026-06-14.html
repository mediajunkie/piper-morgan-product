○ example · Piper hasn't observed anything yet — this is illustrative, and disappears once your Radar has real items.
Why an example here (and nowhere else): the empty state is a new user's first impression — one clearly-labeled example teaches what Radar does before there's real content. The moment a real entity exists, the example is gone and the default view is real-only (every card ● observed). Seed/dev data never renders as real — that's a provenance rule at the data layer, not a card a user sees.
The three binding tells (why this isn't a chat list): 1. Four entity types (Work item · Conversation · Person · Document — chat is one of four). 2. A lifecycle-state badge per card ("what does Piper know about my work"). 3. Honest provenance — default is ● observed only; the empty state's example is unmistakably ○ example; seed data never claims to be real (#1214/#1216). Ordering is attention-first; search spans all types (chat-search folds in as one facet).
