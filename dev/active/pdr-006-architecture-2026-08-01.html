Hosted MCP endpoint & plugin distribution

Piper's server holds tools, connectors and persisted context. The client's model does the reasoning — and composes what the user actually reads.

What changed since the July diagram

Four things moved underneath the version drawn on 18 July, which is why this is a redraw rather than a re-share.

ThenNow
A Web client sat alongside Claude and ChatGPT. Largely deleted by the pivot. Under this model there is no first screen we own.
Capability split was plugin vs. server. Split needs a surface column. "It's in the plugin" is not "it runs everywhere the plugin installs" — web chat has no hooks.
No identity layer drawn. Caller identity is a boundary the whole diagram crosses, and it sits upstream of every existing scoping guarantee.
Arrows pointed one way: client calls, server answers. The return arrow matters. Their model composes what the user reads — our output is an input to someone else's writer.

The consequence worth sitting with

Our first alpha tester's verdict was "just an LLM with extra UI." Under this model that becomes literally true by design — it is their model, plus our tools.

Most of his interface complaints disappear, because there is no interface. But the load-bearing one gets harder: every gram of differentiation now rides on what the tools return, and on whether that survives being paraphrased by a model we don't control.

We have never tested whether our honesty survives recomposition. A hedge we write is a property of text we control; handed to another model, it may not reach the user. This PDR makes that path the default.

Ratified ≠ shippable

#1458 — cross-caller state isolation

Redis, in-process floor/context state, and rate-limiting were never traced. The question moved from "can an anonymous caller see state" to "can caller A see caller B's" — strictly harder. Blocks multi-tenant serving.

#1463 — verification rubric branch

No existing rubric fits a surface where the client's model writes the user-visible reply. Scoring what we compose no longer scores what the user sees. Blocks the plugin surface reaching users.

Also open: mcp.pipermorgan.ai is not deployed, and no public privacy policy exists — a missing one is an immediate rejection at either directory. A directory listing additionally needs domain-ownership verification, which cannot precede the domain existing.

One distinction that keeps getting collapsed

services/mcp/consumer/ is Piper as an MCP client, calling out to other people's servers. mcp.pipermorgan.ai is Piper as an MCP server, being called in. Opposite directions.

A live consumer family — CORE-MCP-MIGRATION #198 — precedents nothing about the server side, which is where the identity risk above actually lives.
