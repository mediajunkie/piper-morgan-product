Two structural questions you raised

1. Does the era chunking still hold? My view: it's overdue for a split.

Era 2 is defined as “blog-first transition + Code-era, Mar 2026 onward.” It has now absorbed 107 published posts over six months and at least three distinct working models: the blog-first transition itself, the alpha/beta push, and the current always-on autonomous-cohort period. An era that contains everything for half a year isn't organising anything — it's just “now.”

If it splits, the seam I'd argue for is the move to the always-on host in late July, because that's when the working model actually changed: continuous duty cycles, agents catching each other's errors in-session, and a documented shift from watching the product to auditing the instruments. That's also, not coincidentally, the material in the slate above — which is an argument for deciding the era question before drafting, since it would shape how Beat 28 lands.

2. Featuring the current post on the blog index. I couldn't verify the rendered page — the index is client-rendered, so fetching it returns a shell with no post content in it. I'm not going to opine on a layout I haven't actually seen.

What I can say editorially: the case for it is strong and it's mostly a syndication problem in disguise. Narratives publish to Medium but deliberately not LinkedIn, and the Ship goes to LinkedIn but not Medium — so for any given post, some part of the audience only ever meets it by landing on the site. If the newest piece isn't visible without scrolling an index, that's the one reader path where we're actively hiding the thing we just made.

The thing I'd want Web to check rather than assume: whether the index is the actual entry point, or whether most arrivals are deep links from syndication. That changes how much the hero is worth.
